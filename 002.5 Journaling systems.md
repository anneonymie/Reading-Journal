I'm trying to design a system for my [[002.5 Journaling systems|reading journal]]. 

## Requirements

- **Robust Metadata control** so I can add covers, publishing data, alternate titles, length, progress, and ratings. 
	- Optionally I would like a scraping ability so I don't have to import it all by hand but this is not a dealbreaker since it would sit on top of the underlying system
	- The addition of custom fields would allow me to note unique elements like what platform I am reading the media on.
	- **Length and progress units.** Each series has a length made of a number plus a unit (chapters, volumes, pages, episodes, etc.).
		- The unit is set at the series level and locks the unit used in journal entries.
		- The quantity is optional, so ongoing series can have a unit (usually chapters) with no total.
	- **Source IDs.** AniList, MangaUpdates, AO3 for scraping and avoiding duplicate entries.
		- Each ID is stored with the name of its source. A work can have IDs from several sources, and each ID can only belong to one work per source.
- **Separate formats are separate works.** A light novel and its manga adaptation are separate entries with their own metadata and progress, connected by a relationship (see Nice to have).
- **Platform agnostic data**: prose (reviews, journal entries, notes) in markdown, images as files not in proprietary formats, structured data in an open format that I can extract and query easily.
- **Library filtering:** by tag, genre, title, or any other metadata fields.
- Advanced Search: by Title, Author, description metadata, or from my journal entries. Allows filtering by allowed tags or banned tags.
- **Tagging**. Alongside genres, I want to be able to add tropes, unique story devices, and content warnings. 
	- An entry for each tag where I can add a description and an auto-populated list of works with that tag
	- High level CWs are listed separately from miscellaneous tags.
	- Clever tag searching: it looks for exact text matches first, then fuzzy searches, then similar tags. And this would be used anywhere on the site that a user types in a tag, including any broad searches, tagging a work, tagging a photo, adding a tag to the CW list (see Nice to have).
- A Review custom field for prose and a 10.0 scale system
- A custom notes field for each series where I can jot down notes about where I am at, what I'm feeling about it— something i can easily access later.
- **A journaling/image interface:** For each piece of media, I want to have a discord-style interface where I can paste in images and commentary, then have that journal viewed in the same chronological manner.
	- Journal entries can be edited and deleted, including automatic entries such as status changes.
	- **Mobile access.** The journal must be usable from my phone. Images can be added by pasting or by uploading from the photo library.
- **Lists.** I want the ability to add media to lists, such as "`wholesome school days mangas`" or "`Discord Recommendations`" where I can list existing entries alongside notes as to why they are on that list. 
	- This would also use a clever search function, like with tags.
- **Status fields.** I would like to have are TBR, Currently Reading, Completed, Dropped, Paused. These differ from lists because a series or piece of media can only have one of these statuses.
	- **Status history.** Every status change is kept, and the current status is the most recent one. This allows rereads (e.g. Completed → Currently Reading → Completed) to be logged and counted.
	- Each status change automatically creates an entry in the series journal, styled differently from a normal entry so it stands out.
	- The journal is a log, not a control panel. Deleting or editing a status-change entry doesn't change the status or the status history. Status and its history are changed from the series page.

## Deployment

- Runs on my personal computer first, then moves to a Docker container on a home server.
- All data lives in one folder (database, images, config), so moving means copying that folder.
- Accessible from my phone on my home network.

Nice to have:
- A field in the journal entry that auto-populates to the most recently reported progress (eg. Ch 22) and allows you to update that progress with each journal entry, so that each journal entry also references where I am in the story. So a journal entry would have not only the date and time, but also a `•` symbol and the progress.
	- Progress can always be entered, even when the series has no total length.
	- **Current progress is a series property.** It can be updated manually on the series page.
	- Creating or editing a journal entry so its progress is farther along than the series progress (in the same unit) updates the series progress once, at the moment the entry is saved. It is not a live link.
	- Deleting a journal entry never changes the series progress.
	- **Rereads.** Changing status from Completed to Currently Reading asks whether to reset progress to 0. Other status changes (e.g. Paused → Currently Reading) leave progress alone.
	- If an entry's progress unit doesn't match the series unit (e.g. the entry says chapters but the series is set to volumes), the system ignores that entry's progress for all calculations and shows a `?` next to it. Hovering the `?` explains that the unit doesn't match the series and the progress is disregarded.
	- *Stretch goal:* a tool that finds journal entries whose unit doesn't match the series and helps the user convert them.
- Spoiler markup. I like the way Discord does it, which is by using the `||` designator. 
- A gallery section for a series where I can highlight specific images, like the pretty ones.
- Tags that can be applied to images like `childhood` or `text attack`
- I would love to also be able to justify those tag applications on a per-media basis so I could say "`Enemies to Lovers - the side couple in Ch. 64 begin as rivals`"
- Tag association: the ability to associate tags as aliases of another tag or nest them within parent tags
- Emojis! 
	- Custom emojis
	- Emojis inserted via shortcode
	- Emoji picker
	- Emoji picker search and keyword association (so typing "smile" brings up multiple smiling emojis even if their shortcodes do not explicitly contain the word "smile")
		- Claude says this has already been somewhat solved by Unicode keyword annotations.
	- The option to render emojis as sticker size (4em instead of 1em)
- Relationships links within series, such as LN to Manga, prequel, side story, same universe, fanfic of. 
- Discord import tool? Something to convert my forum entries to existing media in the system, and then messages in those forum entries are automatically converted to journal entries in a way that cleverly ignores missing data, e.g., progress.
- Error messages and data validation. Fields that can't be used should be grayed out with alt text that explains why.
	- A series total length is only required for percentage progress and completion stats. Those features are unavailable, with an explanation, when the total is missing.
- Statistics page a la Storygraph. But even more robust: the more data the user has, the more chart types become available to them.
- Content Warnings settings page. It auto-populates any tags that have been designated as CWs and allows the user to set per-tag blurring and badges. 
	- This would also apply to images tagged with a CW. It would apply a blur or a badge to those images as appropriate, and everywhere that image is called, these properties would also be called so the setting is consistent across the interface.
	- It would also be helpful to have a generic set of CWs already set: Explicit sex, violence, sexual assault. 
	- And an area at the bottom of the page would allow a person to add pre-existing tags to the CW list.
- A cleanup tool for unused images: finds images nothing uses anymore (e.g. replaced covers) and offers to delete them. It must check every place images are used, including the gallery and custom emoji.
- *Aspirational:* switching between several separate journals (each its own data folder) from within the app, for when switching is frequent. Restoring a backup and moving to a new machine are covered by copying the data folder (see the README).
